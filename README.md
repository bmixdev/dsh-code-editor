# IDE для DeepSeek Harness

`@local/dsh-ide` — главный плагин этого репозитория: рабочая среда в стиле
VS Code внутри правой панели DeepSeek Harness. Своё дерево файлов, вкладки,
быстрый поиск и редактор Monaco с ИИ-подсказками. Плагин не зависит от
встроенного файлового браузера — дерево строит сам Host-половина плагина через
`node:fs` и проверку границ рабочей папки.

Репозиторий поставляет два самостоятельных бандла:

| Бандл | Где лежит | Роль |
| --- | --- | --- |
| `@local/dsh-ide` | корень репозитория | **главный**: IDE с деревом, вкладками, `Ctrl+P` и Monaco |
| [`@local/dsh-code-editor`](editor/README.md) | `editor/` | вспомогательный: компактный редактор Monaco с кнопкой «Редактировать» в превью файла |

Бандлы ставятся и включаются по отдельности. Оба используют один и тот же файл
настроек `~/.dsh/code-editor.json`, поэтому выбранные провайдер, модель и ключ
подсказок общие.

## Возможности

- **Дерево рабочей папки.** Открывается сразу при входе в IDE: ленивая подгрузка
  каталогов, иконки типов файлов, гайды вложенности, переключатель скрытых
  файлов, кнопка обновления и фильтр по имени (при вводе запроса дерево
  переключается на плоский поиск по всему рабочему каталогу).
- **Вкладки.** Несколько файлов одновременно, точка несохранённых изменений,
  закрытие вкладки (крестик или средняя кнопка мыши), `Ctrl+S` — сохранить,
  `Ctrl+Shift+S` — сохранить все, `Ctrl+W` — закрыть вкладку.
- **Быстрый поиск `Ctrl+P`.** Нечёткий поиск по путям рабочей папки, стрелки и
  `Enter` работают как в VS Code.
- **Редактор Monaco.** Одна модель на вкладку, сохранение позиции и скролла,
  подсветка языка, тёмная и светлая темы в палитре VS Code, изменяемая ширина
  дерева.
- **ИИ-подсказки.** Inline-подсказки при наборе и `Ctrl+Space` для принудительного
  запроса; модель и провайдер выбираются в панели настроек, ключ API хранится в
  хранилище секретов DSH. Разрешение отправлять текст модели выдаётся один раз на
  рабочую папку: в редакторе появляется полоса «Включить» / «Не сейчас», а само
  разрешение запоминается в `~/.dsh/code-editor.json` и переживает перезапуск DSH.
- **Вид VS Code.** Узкая панель активности слева (ветка Git, проводник, поиск в файлах,
  изменения, настройки), заголовок секции «ПРОВОДНИК» с действиями, вкладки как в VS Code,
  синий статус-бар, меню `☰` с командами «Сохранить», «Сохранить всё»,
  «Закрыть вкладку», «Открыть файл по имени», «Настройки IDE».
- **Система контроля версий.** Кнопка с веткой на панели активности показывает
  состояние рабочей папки: ветка и HEAD, подготовленные файлы, изменения на диске
  и конфликты. Файл открывается сравнением «индекс → диск» или «HEAD → индекс»,
  `+` и `−` готовят и снимают файлы, сообщение и кнопка «Зафиксировать» создают
  локальный коммит только из индекса. Кнопка «В чат» прикладывает точный патч
  секции в поле ввода чата: для «Подготовленные» — только индекс, для
  «Изменения» — рабочую копию. «Проверить индекс» по явному нажатию отправляет
  staged-патч модели и показывает замечания со ссылками на строки; перед
  проверкой выбирается глубина — «Быстро» (один запрос) или «Глубоко» (до
  четырёх запросов по группам файлов, дольше и дороже), а итог показывает число
  вызовов и время. «Черновик»
  пишет сообщение коммита в поле, но ничего не коммитит. Для конфликтующего файла
  кнопка «Разрешить» собирает base/ours/theirs и показывает предложение в
  редактируемом поле: файл и индекс меняются только по «Применить», а «Отмена»
  оставляет конфликт как был. Внизу — сворачиваемый
  граф истории с
  ветками и слияниями: выбранный коммит подсвечивается, а его файлы показываются
  в том же списке «Изменения»; для слияния можно выбрать родителя. Кнопка ветки
  открывает список локальных веток — переключение, создание с переключением и
  безопасное удаление через `git branch -d` (без принудительного удаления).
  Блок «Сравнить с базой» принимает имя ветки и показывает точку ветвления
  (`git merge-base`), счётчики коммитов впереди/позади и файлы от этой точки —
  не от верхушки базовой ветки.
  «Проект → Рабочие копии…» показывает `git worktree list`, создаёт изолированную
  копию на новой или существующей ветке внутри рабочей папки и удаляет её;
  основная копия и копии с незакоммиченными файлами не удаляются.
  Панель сама обновляется при открытии, возврате фокуса и после сохранения в IDE,
  плюс кнопка «Обновить». Запись недоступна в сессии «только чтение», а Git не
  запускается для удалённых и виртуальных рабочих папок.
- **Статус-бар.** Язык файла, позиция курсора, переводы строк, UTF-8, режим
  «только чтение», текущая модель автодополнения.
- **Сохранение состояния.** Открытые вкладки, активный файл, ширина дерева и
  видимость скрытых файлов запоминаются для каждой сессии
  (`~/.dsh/ide-state.json`).

## Как открыть

Кнопка **IDE** появляется в четырёх местах:

- строка **IDE** на вкладке **Старт** — самое заметное место, ничего открывать не
  нужно;
- кнопка **IDE** в панели ввода рядом с режимами доступа (в сессии она видна
  всегда);
- кнопка **IDE** в инструментах вкладки файла или вкладки **Файлы**;
- заголовок самой вкладки IDE: имя открытого файла.

Вкладка файла открывается сразу с этим файлом и деревом рабочей папки; из
«Старта», панели ввода и «Файлов» IDE открывается на корне рабочей папки —
достаточно выбрать файл в дереве или нажать `Ctrl+P`. На сессию приходится одна
вкладка IDE: повторное открытие не плодит вкладки, а показывает уже открытую.

## Установка

Плагин ставится как обычный локальный бандл DSH. Проще всего — менеджер
плагинов:

```
plugin_manager action=install_bundle target=<абсолютный путь к корню репозитория>
```

Либо вручную в профиле DSH (`~/.dsh/profiles/<profile>/package.json`):

```json
{
  "dependencies": {
    "@local/dsh-ide": "link:C:/path/to/dsh-code-editor"
  },
  "dsh": {
    "profile": {
      "bundles": ["@local/dsh-ide"]
    }
  }
}
```

После установки перезапустите DSH: Host-половина регистрирует маршруты
`/api/ide/*` и раздаёт Monaco по `/ide/vs/*`, клиентская половина добавляет
вкладку IDE и кнопки «IDE» на «Старте», в панели ввода и в инструментах вкладки
файла.

Вспомогательный редактор ставится отдельно и указывает на папку `editor/` — см.
[`editor/README.md`](editor/README.md). Если установить оба бандла, они не
конфликтуют: IDE открывается собственной вкладкой, редактор — вкладкой из превью
файла.

Файл `package.json` профиля должен быть **UTF-8 без BOM** — загрузчик читает его
через `JSON.parse`, и метка BOM валит запуск. Проверить все манифесты можно
командой `npm run check` из корня репозитория.

## Управление

| Действие | Как |
| --- | --- |
| Открыть IDE | кнопка «IDE» — на «Старте», в панели ввода или в инструментах файла; когда вкладка IDE открыта, кнопка подсвечена, повторное нажатие на открытой панели закрывает вкладку |
| Открыть файл | клик в дереве, вкладка остаётся открытой |
| Новый файл / папка | иконки в шапке проводника или меню «Файл → Новый файл…» / «Новая папка…»; имя вводится прямо в дереве, Enter — создать, Esc — отмена; создаётся внутри выбранной папки (или рядом с выбранным файлом) |
| Выбор в дереве | клик по строке подсвечивает файл или папку, выделение определяет, где появятся новый файл и папка |
| Корень рабочей папки | в дереве показан именем текущего воркспейса; клик по нему выбирает корень, каретка сворачивает всё дерево |
| Меню файла в дереве | правый клик по строке: открыть, «Добавить в чат» (файл и выделенные строки), «Добавить строки в чат…» (диалог диапазона), новый файл/папка в этой папке, копировать путь (полный и относительный), «Показать в проводнике ОС» — Windows и macOS выделяют файл в проводнике, Linux открывает содержащую папку, переименовать, удалить |
| Ссылка на файл в чате | правая кнопка по файлу или папке → «Добавить в чат», перетаскивание строки дерева на поле ввода чата, либо `Ctrl+Alt+C` для открытого файла; в черновике появляется чип `@путь` (для папки `@путь/`), подпись несёт диапазон (`state.js:13-19`), а в отправленное сообщение уходит `@путь (строки 13-19)`; клик по чипу открывает файл в панели и выделяет эти строки |
| Дополнительные действия | кнопка «⋯» в шапке проводника: обновить, свернуть всё, скрытые файлы, копировать путь рабочей папки |
| Быстрый поиск | `Ctrl+P` |
| Поиск по содержимому | кнопка «🔍» в панели активности или `Ctrl+Shift+F`: поиск по рабочей папке — строка или регулярное выражение, переключатели `.*` и `ab` (только целые слова); находки сгруппированы по файлам — заголовок с именем, папкой и числом совпадений, ниже строки с номером и подсвеченным совпадением. Клик по находке открывает файл на этой строке, «@» добавляет `@файл строка N` в черновик чата. Поиск локальный и не требует разрешения на подсказки |
| Исключения для AI | `.cursorignore` в корне рабочей папки запрещает отправлять файл модели: поиск его не показывает, Inline Edit отвечает «исключено», правила проекта из него не применяются, а патч в чат, ревью и черновик коммита перечисляют его как пропущенное. `.cursorindexingignore` убирает файл только из поиска — явно открыть и править его можно |
| Git в чат и ревью | «В чат» в заголовке секции «Подготовленные»/«Изменения» или в шапке сравнения прикладывает патч в поле ввода; «Проверить индекс» и «Черновик» — в панели Git. Глубина проверки: «Быстро» — один запрос, «Глубоко» — до четырёх запросов по группам файлов. Проверка идёт только по индексу и только после явного нажатия; замечание открывает строку в сравнении |
| Сохранить / сохранить всё | `Ctrl+S` / `Ctrl+Shift+S` |
| Изменения сессии | кнопка «🕘» в панели активности. Две секции: «Правки ассистента» — контрольные точки, которые ведёт Host (`workspaceChanges`): ход, число файлов и +/− строк, у каждого файла «Принять правки» / «Отменить правки». Клик по файлу открывает сравнение поверх редактора: два окна, слева начало хода, справа конец хода (снимок, а не текущий диск; двоичные и слишком большие файлы помечены, при расхождении снимка с файлом сравнение не показывается). В шапке — число файлов и сумма +/−, кнопки «Принять все» и «Отменить все» для всего хода; внизу — список файлов хода с теми же решениями по каждому («Открыть», «Принять», «Отменить»). Ход, снимок которого Host уже не хранит, остаётся в списке серым без кнопок: список не переписывается задним числом. «Принять правки» ничего не пишет — ассистент уже записал файл, кнопка лишь фиксирует решение; «Отменить правки» возвращает текст начала хода и отказывается, если файл с тех пор изменился, чтобы не потерять чужие правки. «Мои правки» — принятые подсказки с числом добавленных и удалённых строк и статусом «в буфере» / «сохранено» / «возвращено»; клик открывает файл на месте правки, «Вернуть» возвращает прежний текст в буфер при том же условии. История «Моих правок» живёт в памяти сессии, на диск не сохраняется |
| Закрыть вкладку | `Ctrl+W`, крестик или средняя кнопка мыши |
| Файл со строками в чат | `Ctrl+Alt+C` — ссылка `@файл` на открытый файл и выделенные в нём строки; `Ctrl+L` — вставить выделение текстом |
| Меню вкладки | правый клик по вкладке: сохранить, закрыть, закрыть другие, закрыть все, копировать путь |
| Подсказка ИИ | сделать паузу при наборе (по умолчанию 500 мс до запроса), нажать лампочку у строки или Ctrl+Space (во время запроса в строке состояния идёт счётчик миллисекунд); Tab — принять, Ctrl+→ — принять следующее слово, Esc — скрыть и не спрашивать сразу |
| Изменить выделение | выделить код → `Ctrl+Shift+K` или правый клик → «Изменить выделение…», описать изменение, Enter — запрос; «Принять» меняет только буфер (одним Undo), Esc — отмена. «Уточнить» возвращает к тому же выделению и передаёт предыдущий ответ, поэтому следующий запрос может его дополнять; выделять код заново не нужно. Отправка выделения модели разрешается отдельной кнопкой «Разрешить»: разрешение на подсказки Tab её не даёт |
| Объяснить / план | «Чат → Объяснить выделенное…» или «Чат → Подготовить план…» кладут в поле ввода чата готовый черновик с вопросом и фрагментом (`путь:строки`, язык). Ничего не отправляется: запрос уходит только по вашему Enter, и текст можно поправить. Черновик плана можно сохранить («Чат → Сохранить план…»), затем открыть список или передать сохранённую версию в поле ввода другой **открытой** сессии — без отправки модели |
| Сохранённые планы | «Чат → Открыть сохранённый план…»: список версий с датой и объёмом; «В поле ввода» возвращает текст в текущую сессию, «В сессию…» предлагает только сессии с открытым клиентом и кладёт текст в их поле ввода. Хранится локально в `~/.dsh/code-editor-plans.json`, до 50 версий |
| Терминал в чат | «Проект → Запуск терминала в чат…» — ручной захват запуска: команда, код выхода и вывод; до вставки показан точный предпросмотр, вывод ограничен 12 000 символов. Вставляется в поле ввода и не отправляется |
| Пауза Tab | «Подсказки → Приостановить подсказки на 15 минут / 1 час»; в строке состояния появляется «Tab до 15:30», клик по нему сразу возвращает автоподсказки. Ручной `Ctrl+Space` работает и во время паузы |
| Tab по расширению | «Подсказки → Отключить подсказки для .md» выключает автоподсказки только для этого типа файлов; ручной `Ctrl+Space` и принятие уже показанной подсказки работают. В строке состояния появляется «Tab .md выкл», клик возвращает автоподсказки. Список хранится в настройках, до 20 расширений |
| Вторая панель | «Вид → Разделить редактор» открывает рядом другой файл из уже открытых вкладок; панели прокручиваются независимо. Правки сохраняются кнопкой «Сохранить» или `Ctrl+S` во второй панели, «×» закрывает её. На телефоне разделение недоступно |
| Следующий файл | После принятия подсказки Tab новое имя, которое уже встречается в другой открытой вкладке, показывает карточку «Возможно, дальше: путь»; клик открывает файл, «×» скрывает. Карточка ничего не пишет |
| Диагностика Tab | Ошибки и предупреждения линтера рядом с курсором (до трёх строк, не больше пяти сообщений) попадают в запрос подсказки вместе с точной позицией: «Строка N, столбец M: текст». Журнал целиком не пересылается |
| Символ под курсором | «Переход → Символ под курсором» ищет имя в открытых вкладках JS/TS и делит находки на определения и ссылки; клик открывает файл на строке. Это текстовый поиск, а не языковой сервер; закрытые файлы не участвуют |
| Переименовать символ | «Правка → Переименовать символ…» показывает точное число замен по открытым файлам JS/TS и первые строки до/после; «Применить» меняет текст вкладок и помечает их изменёнными, файлы на диске не пишутся. Совпадения в комментариях и строках тоже заменяются |
| Происхождение строки | «Проект → Происхождение строки…» показывает, какие принятые правки Inline Edit покрывали строку под курсором: модель, время, инструкцию и сохранённый ход запрос/ответ. Если записи нет, честно написано «Неизвестно», а не «человек»; Tab, ручной ввод и переименование не отслеживаются |
| Побочный вопрос | «Чат → Побочный вопрос по выделению…» открывает отдельный разговор по фрагменту: история хранится только в панели, в основной чат ничего не добавляется, файл не меняется. Уходит только показанное выделение (до 8000 символов) и вопрос; `.cursorignore` и похожие на секреты файлы отклоняются. «Новый вопрос» очищает историю |
| Режим вопросов | «Чат → Режим вопросов (без записи)» запрещает запись в рабочую папку: сохранение, создание папок, переименование и удаление, подготовку и коммит индекса, ветки и применение разрешения конфликта получают отказ `ask-mode`. Запрет хранится в настройках и проверяется Host-ом, а не только интерфейсом; чтение, поиск, ревью и черновики продолжают работать |
| Тесты проекта | «Проект → Запустить тесты (npm test)…» выполняет только скрипт `test` из корневого `package.json`, показывает итог, список упавших тестов и вывод; клик по падению открывает файл на строке. «Повторить» запускает снова, «Остановить» прерывает; в read-only-сессии запуск запрещён |
| Спросить о проекте | «Чат → Спросить о проекте…»: вопрос на естественном языке, локальный поиск по словам вопроса и короткий ответ модели со ссылками `путь:строка`. Клик по источнику открывает строку. Отправляются только найденные строки (до 40), файлы из `.cursorignore` не попадают; ответ ничего не меняет |
| Найти в разговорах | «Чат → Найти в разговорах…» ищет по тексту прошлых сообщений через индекс Host-а (`sessionQuery`) и показывает фрагменты, сессию и время. Поиск ограничен разговорами этой рабочей папки; клик открывает найденную сессию. Модель не вызывается, файлы не меняются |
| Источник из разговора | У найденного фрагмента кнопка «Приложить» читает ровно один ход через `sessionQuery.readEvent` и показывает объём: заголовок, число символов, первые 1200 знаков. «Вставить в чат» кладёт в поле ввода этот ход (до 8000 символов), а не всю сессию; модель не вызывается, файлы не меняются |
| Журнал отладки | «Проект → Журнал отладки…» собирает гипотезу, шаги воспроизведения, два прогона, путь временных логов и отметку об очистке. Показывает точный предпросмотр и вставляет блок в поле ввода; отладчиком не является, точки останова и процессы не управляются |
| Пакет заметок | «Чат → Пакет заметок…» собирает пронумерованный список замечаний: текст, файл и строку можно взять из выделения. «Вставить в чат» отправляет один согласованный список (до 50 заметок, 1000 символов на заметку) |
| Экскурсия по коду | «Проект → Экскурсия по коду…» собирает локальный маршрут ревью: текущая строка файла и короткое пояснение, порядок меняется стрелками. «Далее»/«Назад» открывают шаг в редакторе; маршрут не пишется в репозиторий и не уходит модели (до 40 шагов, 240 символов на пояснение) |
| Панель траектории | Ctrl+Space всегда открывает её и показывает попытку; клик по строке открывает тот файл и заново рисует записанную подсказку, не вызывая модель |
| Палитра команд | `Ctrl+Shift+P` или «Вид → Палитра команд…»: те же пункты, что в меню, с поиском по названию и разделу; Enter запускает первый подходящий. Неактивные пункты видны, но не запускаются |
| Панель вывода | Ctrl + обратная кавычка или меню «Вид → Показать панель вывода»; при включённом чате панель открыта постоянно, а отключается настройкой |
| Настройки | кнопка «⚙» в шапке IDE или меню «Файл → Настройки IDE…»; все клавиши выше, кроме Tab и Esc, переназначаются в разделе «Клавиши»: впишите сочетание (`Ctrl+Shift+K`) или верните значение по умолчанию кнопкой «↺». Непонятное или занятое сочетание подсвечивается и не сохраняется |
| Правила проекта | кнопка «Правила» в строке состояния показывает цепочку `AGENTS.md`, `CLAUDE.md`, `.cursorrules` и `.cursor/rules/*.mdc` от корня рабочей папки к папке файла. Найденные правила видны всегда, но к «Изменить выделение» попадают только помеченные «применяется»; Tab и чат их не получают |
| Подключить модель | «Подсказки → Подключить модель…» или кнопка в настройках: провайдер, модель, ключ, одна кнопка |
| Скрыть/показать дерево | иконка панели слева или меню «Файл» |
| Ширина дерева | перетащить разделитель |
| Переставить панели | кнопка «⇄» в шапке IDE или меню «Вид → Проводник справа/слева» — дерево переезжает за редактор и обратно; сторона запоминается в состоянии сессии |

## На телефоне

IDE выбирает раскладку по ширине собственной панели, а не окна: на телефоне
правая панель DSH открывается на весь экран, и интерфейс перестраивается в
компактный режим. На настольном компьютере с широкой панелью всё остаётся как
раньше; в узкой панели на настольном экране (меньше 480 px) IDE тоже переходит
на компактную раскладку, потому что дерево и код там уже не помещаются рядом.

- В шапке остаются четыре кнопки: ☰ — проводник, ⋮ — все меню одной шторкой,
  лупа — быстрый поиск, ⚙ — настройки. Строка меню и панель активности
  скрываются, имя открытого файла показывается по центру.
- Проводник — выдвижная панель поверх кода (слева или справа, как выбрано) с
  затемнением; тап по затемнению закрывает её, а после открытия файла она
  убирается сама.
- Размеры под палец: строки дерева и вкладки не ниже 36–40 px, пункты меню
  44 px, поля ввода 16 px (иначе iOS зумит страницу при фокусе), ручки
  перетаскивания шире, у панели вывода появился видимый захват.
- В редакторе по умолчанию шрифт 16 px, перенос строк включён, липкая
  прокрутка и миникарта выключены — код читается на узком экране без
  горизонтальной прокрутки.
- Размер текста меняется тремя способами: кнопки A− и A+ в правом углу строки
  состояния, щипок двумя пальцами прямо по коду и пункты «Вид» в меню ⋮
  (там же сброс к 16 px). Выбранный размер запоминается в состоянии сессии, а
  при смене раскладки без ручной настройки возвращается к 16 px на телефоне и
  13 px на компьютере. На настольном компьютере работают привычные Ctrl+=,
  Ctrl+- и Ctrl+0.
- Настройки, быстрый поиск и диалоги открываются на всю ширину или шторкой
  снизу; навигация настроек превращается в горизонтальные чипы, учитываются
  безопасные отступы экрана (вырез, полоса жестов).
- Долгое нажатие на строке дерева открывает контекстное меню; если система его
  не показывает, переименование и удаление выбранного файла есть в меню «⋯»
  проводника.

Компактный режим включается, когда панель уже 480 px, либо когда она уже
700 px и при этом устройство сенсорное (нет мыши) или окно узкое.

## Меню

«Файл» отвечает за документы, «Правка» — за текст и выделение, «Вид» — за панели и оформление, «Переход» — за навигацию. В «Чат» собраны вопросы, цитаты, планы и заметки. В «Проект» находятся рабочие копии, происхождение строки, экскурсия по коду, тесты и журнал отладки. Настройка модели и пауза автодополнения находятся в «Подсказках», горячие клавиши — в «Справке».

Меню использует язык страницы: английский для `en` и `en-*`, русский по умолчанию. В палитре и мобильном меню используются те же команды. Постоянно недоступные действия не показываются. В контекстном меню проводника действия зависят от выбранного объекта: например, корневую папку нельзя переименовать или удалить.

Планы, пакет заметок, рабочие копии, экскурсия, журнал отладки и форма переноса вывода терминала открываются вкладками рядом с «Траекторией» и «Чатом». Переключение между вкладками не закрывает форму и не сбрасывает её черновик.

«Новый файл» создаёт пустой файл внутри рабочей папки (родительские каталоги
создаются, существующий файл не перезаписывается) и сразу открывает его.

## Панель вывода

Внизу редактора есть панель как в VS Code. При включённой настройке
«Показывать чат в панели» (по умолчанию) панель открыта постоянно и не
закрывается крестиком или Ctrl + обратной кавычкой; выключите настройку, чтобы
вернуть прежнее поведение и скрыть вкладку «Чат». `Ctrl+Space` открывает панель
при каждом ручном запросе подсказки. Высоту панели можно менять, потянув
разделитель над ней; она запоминается в состоянии сессии (`~/.dsh/ide-state.json`).

- **Траектория** — строка на каждый запрос автодополнения: время, файл, провайдер
  и модель, режим (авто или `Ctrl+Space`), сколько символов контекста ушло,
  длительность, результат («+N символов») или причина, почему ответ пустой.
  Клик по строке открывает записанный файл и заново рисует ту подсказку; если
  файл с тех пор изменился, редактор сообщает, что подсказка больше не подходит.
  Правый клик по строке → «Принять правку» применяет её без повторного запроса
  к модели. Старая подсказка снимается, когда в сессии начинается новый ход и
  когда он завершается. Для «Изменить выделение» строка «правка» появляется
  сразу и показывает, сколько миллисекунд модель уже думает; после ответа
  остаются точная длительность, модель и число изменённых символов.
- **Чат** показывает системную инструкцию, отправленный текст и ответ только для запросов, выполненных с настройкой «Полная диагностика подсказок», — включая правки выделения. По умолчанию эти копии не передаются в панель. Если выбранная строка «Траектории» не несёт диалога (например, ещё думающая правка), чат показывает ближайшую запись с диалогом, а не пустоту. Выключение настройки очищает копии из текущей панели, но не отключает сами запросы к модели.

Это же объясняет самый частый вопрос «почему подсказки не работают»: у
рассуждающей модели (`reasoning`) скрытое размышление съедало весь бюджет
токенов, и ответ приходил пустым. Теперь плагин:

- запрашивает у модели минимальный advertised `reasoningEffort`, оставляя бюджет
  на код;
- поднимает лимит ответа до 900 токенов;
- возвращает причину пустого ответа в панель, вместо молчаливого «ничего».

## Настройки

Страница настроек (шестерёнка в шапке, `Ctrl+,` или «Файл → Настройки IDE…»)
сделана как в VS Code: заголовок с поиском, разделы слева, строки «название и
описание слева, контрол справа». Значения хранятся в общем файле
`~/.dsh/code-editor.json` (тот же, что использует вспомогательный
`@local/dsh-code-editor`) и применяются сразу:

- провайдер и модель автодополнения (со списком из живого каталога DSH);
- кнопка «Обновить каталог» и сообщения провайдеров, которые не отдали модели;
- автоподсказки при наборе;
- показывать чат в панели (по умолчанию включено; выключение скрывает вкладку
  «Чат» и закрывает панель, открыть её снова можно вручную);
- предел ожидания ответа в миллисекундах (1000–60000, по умолчанию 6000);
- имя ключа API и сам ключ — значение уходит в хранилище секретов DSH, в файл
  настроек попадает только имя (`apiKeyRef`);
- сколько символов до и после курсора отправлять в модель (200–20000 и 0–8000);
- раздел «Подсказки ИИ»: **системная инструкция** — текст, с которым редактор
  обращается к модели (пустое поле — стандартная инструкция, она показана серым;
  подстановки `{{answerLines}}`, `{{language}}`, `{{file}}`), уровень рассуждений
  модели (`off` — быстро, без
  «размышлений»), задержка перед запросом и сколько
  миллисекунд собирать текст после первого символа, сколько строк до и после
  курсора видит модель, длина ответа, сколько строк после курсора разрешено
  переписать, размер файла, пауза после Esc, замена хвоста строки, приём по
  слову (`Ctrl+→`), повторный запрос после приёма, подсказки в комментариях,
  подсветка текста под замену, причины отказа в панели;
- раздел «Проверки подсказок»: пробельные правки, допустимый рост ответа, порог
  и окно памяти отклонённых подсказок, дубль следующей строки, повтор диапазона,
  отмена только что удалённой правки.

## Механика подсказок

Поток повторяет Cursor Tab: клиент присылает буфер, версию модели, отклонённые и
удалённые фрагменты; Host собирает окно контекста, спрашивает модель, а затем
**сам планирует правку** — вставку или замену нескольких строк после курсора — и
прогоняет её через проверки «плохих случаев». Клиент только рисует план серым
текстом (а удаляемый хвост подсвечивает), принимает его по `Tab`/`Ctrl+→` и
запоминает, что пользователь отклонил. Все пороги и проверки — те же настройки,
что выше; разбор исходной механики с адресами в бандле Cursor лежит в
[docs/cursor-tab-mechanics.md](docs/cursor-tab-mechanics.md).

### Фантомные правки по всему файлу

Одной вставки у курсора мало: набрав `main(f)` под `def main():`, пользователь ждёт,
что редактор предложит привести сигнатуру в порядок, а не только допишет символы.
Поэтому при `multiEdit` (по умолчанию включено) Host отправляет файл целиком с
отметкой `⟦КУРСОР⟧` и просит ответ из двух частей: продолжение у курсора и список
правок `find`/`replace` в других местах. Правка применяется, только если её `find`
встречается в буфере ровно один раз и не задевает курсор; всё остальное
отбрасывается, а не угадывается. Однострочная замена рисуется на месте: старый
фрагмент остаётся розовым, замена дописывается зелёным фантомным текстом в той же
строке. Многострочная правка не печатается поверх кода — предлагаемые строки
реально вставляются в буфер над заменяемым блоком (зелёный фон), а заменяемые
строки подсвечиваются розовым с зачёркиванием. `Tab` оставляет вставленные строки и
удаляет розовые, `Esc` удаляет вставленные и возвращает буфер как было; в файл
ничего не попадает, пока не нажат `Tab`. Ответ, в котором есть только правки, тоже
показывается: панель пишет `edits-only`, а не «модель не вернула продолжение».

Структурированный ответ стоит модели на 2–3 секунды дольше, поэтому он запрашивается
по `Ctrl+Space`, а обычная пауза при наборе покупает быстрое продолжение у курсора.
Настройка `multiEditAuto` («правки при наборе») включает правки и на паузе.

Модель подсказок выбирается в настройках. Если она не выбрана, Host берёт быструю
модель-«сестру» из каталога провайдера (на этом шлюзе — `glm-5.3-flash`), а не модель
сессии: думающая модель тратит скрытые рассуждения, и подсказка приходит через 3–6 с
или не приходит вовсе. Галочка «Брать быструю автоматически» стоит прямо под выбором
модели; пустой выбор с включённой галочкой помечен «· авто». Выключите её — тогда
подсказки идут на текущей модели сессии, а инструкция просит её писать сразу кодом,
без пояснений (галочка «сразу кодом»). Скрытые рассуждения это не отключает: их режим
задаёт маршрут, поэтому на `deepseek-v4.1-flash` ожидайте 3–4 с, а на `glm-5.3-flash` —
около секунды.

Настройки группы «Подсказки ИИ»: `multiEdit` (просить правки), `multiEditAuto`
(и на паузе при наборе), `maxEdits` (сколько принимать, 0 — выключить) и
`wholeFileContext` (отправлять файл целиком, а не окна вокруг курсора). Ради
структурированного ответа такие запросы ждут конца потока: обрезка по
`flushAfterMs` оставила бы `EDITS:` с половиной JSON. Лимита токенов по умолчанию нет: запрос уходит без `maxTokens`, и модель
останавливается сама — потолок ниже её возможностей обрезал ответ посреди правки.
Настройка «лимит токенов ответа» ставит потолок обратно, если маршрут считает по
токенам. Если ответ всё же обрезан, готовые правки из начала списка сохраняются, а
обрыв внутри `why` не мешает принять правку: `find` и `replace` уже целые.

Скорость — часть механики. Подсказка просит у модели уровень рассуждений, который
не тратит бюджет на «размышления», отдаёт текст, как только он пошёл, и ограничена
по умолчанию 6 секундами (поле «максимальное ожидание», до 60). Главное — модель:
на замерах `glm-5.3-flash` отвечает за
0,8 с, а `deepseek-v4.1-flash` за 3,2 с и на «думающих» настройках может не
ответить вовсе. Поэтому модель подсказок стоит выбрать отдельно от модели сессии;
в «Траектории» видно, какая модель ответила, откуда она взялась и с каким уровнем
рассуждений. Формулировку системной инструкции можно править в настройках: пустое
поле — стандартный текст, а `{{answerLines}}`, `{{language}}` и `{{file}}`
подставляются в запрос.

Если набранное совпадает с началом простой подсказки, редактор оставляет её хвост без нового запроса: `ret` из `return result` оставит `urn result`. `Tab` принимает оставшийся текст, `Ctrl+→` — следующее слово. Несовпадение или `Esc` скрывает подсказку. Незавершённый запрос обрывается при следующем нажатии,
пауза перед запросом — 500 мс; после приёма следующий запрос по умолчанию не
делается. Выделение мышью и перемещение курсора подсказку не запрашивают.

## Безопасность

- Пути проверяются через `ctx.fs.resolve` / `ctx.fs.contains`, включая защиту от
  символических ссылок: за пределы рабочей папки дерево не выходит.
- Скрытые каталоги (`.git`, `node_modules`, `dist`, `build`, `.venv`, `target` и
  другие) не скрываются: дерево показывает всё, а читает каталог только когда
  его раскрывают. В поиске остаются исключены только хранилища версий
  (`.git`, `.hg`, `.svn`), установленные зависимости (`node_modules`,
  `bower_components`, виртуальные окружения) и их кеши — остальное, включая
  `dist` и `build`, ищется.
- Каталог отдаётся страницами по 400 записей (не больше 2000 за запрос);
  следующая страница запрашивается строкой «Показать ещё» в конце списка.
- Файлы больше 1 МиБ не открываются; бинарные и не-UTF-8 файлы отклоняются.
- Ключи API никогда не пишутся в файл настроек и не возвращаются клиенту в
  открытом виде — только маска из хранилища.

## Тесты

Из корня репозитория:

```
npm run check        # манифесты: UTF-8 без BOM и валидный JSON
npm test             # тесты главного бандла @local/dsh-ide
npm run test:editor  # тесты вспомогательного @local/dsh-code-editor
npm run test:all     # оба набора
```

`tests/host.test.mjs` поднимает фейковый контекст, собирает маршруты `/api/ide/*`
и проверяет дерево, быстрый поиск, открытие/сохранение, состояние сессии, общие
настройки и деградацию без хранилища ключей. `tests/scm.test.mjs` собирает
настоящие временные репозитории и проверяет чтение состояния, сравнение сторон,
подготовку, частичный коммит, историю с ветками и слияниями, а также создание,
переключение и безопасное удаление веток. `tests/client.test.mjs` загружает
бандл через `__ModuleLoader__` с заглушкой React и проверяет регистрации: тип
вкладки, слоты, кнопку «IDE», защиту от закрытия грязных вкладок, заголовок
вкладки, раскладку графа и разбор групп изменений. `tests/tab.test.mjs` проверяет
механику подсказок без редактора: план
вставки и замены, эхо уже набранного текста, CRLF, проверки «плохих случаев» и
границы слова для `Ctrl+→`.

Тесты редактора лежат в `editor/tests/`; `editor/tests/sync.test.mjs` сверяет
общие модули с корневыми копиями.

## Ограничения

- Один редактор на вкладку правой панели; одновременно открытые IDE-вкладки в
  разных сессиях независимы.
- Быстрый поиск `Ctrl+P` ищет по путям; поиск по содержимому — отдельная панель
  «Поиск в файлах»: подстрока или однострочное регулярное выражение, при желании —
  только целые слова. Индекса нет, многострочные шаблоны не поддерживаются;
  сложный шаблон выполняется синхронно и может замедлить Host. Замер
  `bench/search-compare.mjs` (4 МБ, 70 000 строк, 1000 файлов): поиск по дереву —
  7–273 мс в зависимости от плотности совпадений, индекс — 12–13 мс на запрос, но
  его сборка занимает около 240 мс и требует слежения за изменениями. Выигрыш
  только на разреженных повторных запросах, поэтому индекс пока не ведётся.
- Сравнение показывает две версии целиком; правки по фрагментам, `git push`,
  `reset --hard`, `clean` и удаление неотслеживаемых файлов из панели не входят в
  эту версию.
- Патч для чата и ревью ограничен 256 КиБ и 40 файлами; двоичные, пустые и
  похожие на секреты файлы перечисляются как пропущенные, а не отправляются
  молча. Ревью видит только индекс, выполняется по явному нажатию и не меняет
  Git; при смене индекса показанный результат помечается устаревшим. Глубокое
  ревью — это тот же промпт по группам файлов: не более четырёх вызовов, и при
  большем индексе остаток честно помечается усечённым.
- Разрешение конфликта ограничено 512 КиБ на все три стороны; двоичные файлы не
  отправляются. Текст модели применяется к индексу и файлу только по кнопке
  «Применить» и только к той ревизии, для которой был получен.
- Исключения читаются только из корня рабочей папки: вложенные
  `.cursorignore` не поддерживаются. Понимается подмножество gitignore —
  комментарии, `!`, завершающий `/`, ведущий `/`, `*`, `**` и `?`; регулярные
  выражения и экранирование пробелов не поддерживаются. Скрытие файла в дереве
  не является исключением: защищают только эти два файла.
- Правила проекта читаются только для открытого файла: `AGENTS.md`, `CLAUDE.md`,
  `.cursorrules` и `.cursor/rules/*.mdc` по пути от корня к папке файла. Они
  применяются только к «Изменить выделение» — Tab и чат их не получают. Пределы:
  16 файлов, 32 КиБ на файл и 64 КиБ суммарно; глобы, front-matter и удалённые
  наборы правил не поддерживаются, а слишком большой файл перечисляется как
  пропущенный.
- Сохранённые планы лежат локально и передаются только в поле ввода уже открытой
  сессии; автоматическая отправка, выбор сессии, которая ещё не открыта в этом
  клиенте, и синхронизация между устройствами не входят в эту версию.
- Терминала внутри плагина нет: «Запуск терминала в чат…» принимает команду,
  код выхода и вывод вручную, показывает состав и вставляет его в поле ввода.
  Автоматически подхватывать запуски из внешнего терминала или истории DSH
  эта версия не умеет.
- Отключение Tab по расширению действует на автоматические и фоновые запросы;
  ручной `Ctrl+Space` остаётся доступен. Расширение определяется по последней
  точке в имени, файлы без расширения (`.env`, `Makefile`) не отключаются.
- Вторая панель показывает только файл из уже открытых вкладок; перетаскиваемого
  разделителя, третьей панели и запоминания раскладки между сессиями нет.
  Подсказки и «Изменить выделение» работают в основной панели.
- Карточка «Следующий файл» — локальная эвристика по открытым вкладкам, а не
  предсказание модели: она показывает файл, где уже встречается новое имя, и
  ничего в нём не меняет.
- В запрос Tab попадают только ошибки и предупреждения линтера в пределах трёх
  строк от курсора, не больше пяти, с обрезкой сообщения до 300 символов.
  Полный журнал диагностики не отправляется.
- «Символ под курсором» работает по тексту открытых вкладок JS/TS: определения
  распознаются по `function`/`class`/`const`/`let`/`var` и присваиванию функции.
  Перегрузки, типы из зависимостей, закрытые файлы и точная семантика требуют
  языкового сервера и не поддерживаются.
- Переименование тоже текстовое: заменяются все целые слова в открытых файлах
  JS/TS, включая комментарии и строки. Файлы на диске не меняются до сохранения,
  а `setValue` в затронутых моделях сбрасывает их историю Undo.
- «Происхождение строки» опирается только на принятые правки Inline Edit в текущей
  сессии: записи живут в памяти и не переживают перезапуск, а Tab, ручной ввод,
  переименование и внешние изменения не дают доказательств. Поэтому «неизвестно»
  означает отсутствие записи, а не авторство человека.
- «Режим вопросов» — это настройка плагина, а не sandbox-политика Harness:
  он закрывает только записи, которые идут через плагин, и не мешает другим
  инструментам сессии менять ту же папку.
- «Побочный вопрос» не создаёт отдельную сессию DSH: это панель с собственной
  историей обменов, которая живёт до закрытия и не попадает в журнал сессии.
- «Спросить о проекте» — это поиск по словам вопроса, а не семантический
  индекс: берутся до шести слов длиннее двух букв, до 40 строк и до 12
  результатов на слово. Ответ модели разрешён только по этим строкам, ссылки
  проверяются по `путь:строка`; если совпадений нет, модель не вызывается.
  Ответ не меняет файлы, а история вопросов не сохраняется.
- «Найти в разговорах» требует сервис `sessionQuery`, который подключает
  установленный Harness; без него маршрут отвечает `unavailable`. Индекс
  ищет по точным словам (FTS5), запрос ограничен 200 символами и 20
  результатами, а выборка — разговорами с тем же записанным `cwd`, что у
  открытой рабочей папки. Открывается сессия целиком: перейти к конкретному
  сообщению из IDE API пока не позволяет.
- «Приложить» берёт только выбранный ход (тот `seq`, который вернул поиск):
  в поле ввода попадает до 8000 символов, всё остальное в документе и всей
  сессии остаётся за пределами текущего разговора. Предпросмотр показывает
  полный объём хода и отдельно отмечает обрезку; вложения не отправляются
  модели сами по себе.
- «Журнал отладки» — это заметка для чата, а не отладчик: плагин не ставит
  точки останова, не запускает и не останавливает процессы, а поле «логи
  убраны» остаётся обещанием автора, которое блок только фиксирует. Поля
  обрезаются до 4000 символов, весь блок — до 16000.
- «Пакет заметок» нумерует только то, что вы добавили вручную: заметки
  живут до закрытия панели, не сохраняются между сессиями и не привязаны к
  diff или чужой странице. «Из выделения» берёт текущую строку или выделенный
  текст и подставляет путь с номером строки.
- «Экскурсия по коду» — локальный маршрут в памяти панели: шаги не сохраняются между
  сессиями, не публикуются и не проверяются на существование файла при
  добавлении. Переход только открывает файл и строку; ничего не пишется, а
  внешнего хостинга Origin у плагина нет.
- Сравнение ветки показывает только список файлов от `merge-base` и счётчики;
  отдельного diff «вся ветка против базы» в панели нет — откройте файл или
  сравнение индекса. Ветка задаётся вручную локальным именем; удалённые
  `origin/…` не подставляются автоматически.
- Рабочие копии создаются только внутри открытой рабочей папки и только от
  текущего HEAD; отдельная копия не открывается в IDE автоматически. Удаление
  без `--force` отказывает при незакоммиченных файлах, а интерфейс не предлагает
  принудительное удаление — такие копии убираются в терминале.
- Запуск тестов ограничен скриптом `test` из корневого `package.json` (без
  аргументов и выбора других скриптов), таймаутом 180 с и первыми 2 МиБ вывода;
  переход к падению берётся из TAP-поля `location` или первой строки стека в
  скобках. Произвольные команды и отдельные тестовые файлы не запускаются.
- Рефакторинги, LSP и запуск тестов из IDE не входят в эту версию.

## English summary

`@local/dsh-ide` is the main plugin of this repository: a VS Code style IDE in
the DeepSeek Harness right sidebar, with an explorer tree, file tabs, quick open
(`Ctrl+P`), a Monaco editor with AI inline suggestions, a Source Control panel
(status, per-side diffs, staging and local commits, history graph, branch
comparison from the real merge base, worktree copies created and removed inside
the workspace, chat patches,
staged review with quick/deep depth, commit message drafts, conflict resolution reviewed before it is
written, project-rule preview, saved plan drafts, terminal captures, Tab
snooze and per-extension Tab opt-out, a second independently scrolled editor
pane, a follow-up card for the next open file, nearby linter diagnostics in the
Tab prompt, textual definitions and references across open JS/TS tabs, a line-provenance
card that says “unknown” instead of guessing a human author, an
ask-only mode that makes the Host refuse every workspace write, a side-question
panel whose transcript never enters the main chat, and a
rename preview that only marks buffers dirty, and an npm-test runner that jumps
to the failing line, an Explore dialog that answers a natural-language question
from locally found lines and links only those lines, a conversation search
backed by the Host session index and limited to the open workspace, an attach
action that previews one earlier turn's exact size and inserts only that turn
into the composer, a debug journal that records a hypothesis, reproduction
steps, two runs and an explicit temporary-log cleanup note without pretending
to be a debugger, a numbered notes pack that turns selected lines into one
agreed review list, a local code tour of file/line stops with short notes
(nothing is written or hosted), and two AI ignore scopes:
`.cursorignore` blocks a file
from search, Inline Edit, rules and chat patches, while `.cursorindexingignore`
hides it from search only), a VS Code
style menu and status bar, and per-session layout state. It opens from the IDE
button on the Start tab, in the composer row, or in the file/Files tab actions.
Install with
`plugin_manager action=install_bundle target=<repository root>`; run tests with
`npm test`. Content search stays index-free: `bench/search-compare.mjs` measured
7–273 ms per tree scan against 12–13 ms per indexed query after a ~240 ms build,
so an index only pays off for sparse repeated queries and is deferred. The
repository also ships a secondary, optional Monaco editor bundle
in `editor/` (`@local/dsh-code-editor`, opened from the Edit button in the
document preview) with its own README and `npm run test:editor`. MIT licensed.
