# Cursor → dsh-ide: расширенный реестр возможностей

26.11.2026. Объект сравнения — **пользовательский сценарий в панели `@local/dsh-ide`**, а не совокупность всех команд и инструментов Harness. Сверка: [официальный индекс Cursor](https://cursor.com/llms.txt), [управление IDE](../README.md#управление), [ограничения IDE](../README.md#ограничения), [инвентарь установленного Cursor](cursor-extension-inventory.json), [разбор редакторных механик](cursor-mechanics.md). Документация Cursor новее исследованной локальной сборки; функции Agents Window, облака и Enterprise не приписываются обычному редактору.

**Как читать.** `Δ` — есть близкий сценарий, указан именно недостающий шаг; `−` — ограничение явно указано в README; `?` — готовый интерфейс не подтверждён документацией проекта, проверить в живой IDE перед постановкой; `↔` — задача интеграции с Harness или внешней системой, не предложение написать второй движок. Это продуктовый реестр, не доказательство отсутствия каждой функции в установленном профиле. Внутри каждой очереди выше стоят более частые действия с меньшим числом зависимостей. Все формулировки справа — предлагаемая адаптация, не описание реализации Cursor.

## Что не считать пробелом

В [действующем описании](../README.md#управление) уже есть файл/папка/диапазон в чат, переход к результату текстового поиска, правка выделения с отдельным разрешением, принятие Tab по слову, палитра команд, переназначение клавиш, снимки хода и возврат изменений. Наличие этих функций не закрывает, например, межфайловый Tab, регулярный поиск или замечания ревью. Для пограничных случаев сверять реальное поведение, а не отсутствие названия Cursor. Модели поштучно, тарифы, переводы, совместимость со всем VS Code Marketplace, собственный Git-хостинг, SSO/SCIM и магазины приложений не являются самостоятельными задачами редактора.

## Как превратить реестр в поставки

1. **Проверить дельту на одном тестовом репозитории.** Для первого пакета записать команду/жест, существующий результат и недостающий шаг. Проверить локализации и команды плагина; если готовый сценарий найден, снять пункт или оставить только улучшение обнаруживаемости. Не принимать `?` за доказанное отсутствие.
2. **Релиз 1: поиск и Git (1–4).** №1 независим. Общий фундамент №2–4 — снимок с идентификатором репозитория и ревизии, лимит объёма, редакция секретов и предпросмотр отправки. Гейт: staged и unstaged в одном файле не смешиваются; устаревший ответ отмечен; создание черновика не меняет Git.
3. **Релиз 2: путь от выделения до результата (5–14 выборочно).** Начать с уточнения Inline Edit и разрешения конфликта. Гейт: отмена сохраняет буфер, поздний ответ не применяется к другой ревизии, переход к другому файлу сам по себе ничего не записывает.
4. **Отдельные прототипы:** языковой сервис (15–17), поиск по большому проекту (18–21), браузер (30–36), изолированные задачи (39–41). Для каждого сравнить с текущим способом на одной задаче. Не строить индекс без ускорения, второй агентский backend без недостающего контракта или просмотр сетевого трафика без редактирования секретов.
5. **Платформа (47–68)** — отдельные инициативы, не условие локального релиза. Сначала определить владельца, доступный API, стоимость, права и правила хранения. Начать с читающих интеграций; Git-запись, отправка во внешнюю систему и удалённый запуск не следуют автоматически из открытия карточки.
