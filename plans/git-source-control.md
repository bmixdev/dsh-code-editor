# Git в dsh-ide: план реализации по экрану образца

Целевой сценарий: открыть IDE в рабочей папке → нажать значок ветки рядом с проводником → увидеть изменения даже от внешнего редактора → щёлкнуть файл и сравнить его в центральной области → подготовить файлы, ввести сообщение и создать локальный коммит → увидеть его в графе. Чат DSH и несохранённые вкладки не должны исчезать. На широком экране список и граф остаются видимыми при открытом сравнении.

## От чего отталкиваться

- Менять корневой `@local/dsh-ide` (при анализе версия 0.6.0), не второй пакет `editor/`: [README](../README.md#L9-L16). Перед началом проверить `git status --short`, сохранить чужие изменения. Старый [план паритета](reference-editor-parity-plan.md) описывает более раннюю версию.
- [index.js](../index.js#L319) уже регистрирует операции IDE через `ctx.connection.fetch`; [sessionOf и open](../index.js#L383-L425) получают рабочую папку из сессии и проверяют границу. Расширять эту таблицу и клиентский `call`, не добавлять HTTP-сервер, глобальный слот DSH или инструмент агента.
- [agentChanges.js](../agentChanges.js#L1-L12) хранит индекс ходов живых сессий. Это не индекс Git: он не является источником ни внешних изменений, ни истории коммитов. Существующий просмотр и отмену правок агента оставить отдельными.
- [client.js](../client.js#L6662-L6709) уже создаёт две модели Monaco, включает side-by-side, подсветку и overview ruler, переключается на unified в компактном режиме и освобождает ресурсы. Переиспользовать этот показ, но не действия принятия/отката агента. Новая библиотека diff не нужна. Ориентир поведения — Source Control внешнего редактора-образца; внешний вид — скриншот из задачи, не спецификация внутренних API образца.

## Порядок работы

Выполнять по одному шагу. После каждого запускать его тест и существующий `npm test`; не продолжать с красным тестом. Имена `scm*` ниже — предлагаемые новые маршруты, а не сервисы Harness.

### 1. Получить проверяемый снимок рабочего дерева (Host, без UI)

Создать `scm.js` для Git-операций; `index.js` оставить адаптером сессии/политик. Добавить файл в `package.json.files`, новый `tests/scm.test.mjs` — в явный список `scripts.test`. Сначала реализовать `scmStatus({sessionId}) → {branch,head,entries,revision}`. Элемент: `{path,oldPath?,indexStatus,worktreeStatus,kind}`; путь относительно корня Git, разделитель `/`. `revision` — идентификатор снимка, не только SHA коммита.

Для первой версии поддержать одну локальную папку-сессию, совпадающую с корнем worktree: проверить канонические пути после `git rev-parse --show-toplevel`. Если папка вложена, предложить открыть корень вместо расширения доступа к соседним файлам. Никакого авто-init или обхода вложенных репозиториев. Не путать `.git`-файл linked worktree с отсутствующим репозиторием. Не запускать системный Git для удалённой/виртуальной ФС или если действующие ограничения DSH не позволяют такую операцию. Если соблюдение политики невозможно подтвердить, отключить операцию, не подменять её shell-вызовом.

Запускать фиксированные команды через argv без shell; не принимать cwd, команду, произвольную ревизию или флаги от клиента. `git status --porcelain=v2 --branch -z --untracked-files=all`: разобрать записи `1`, `2` (для переименования старый путь идёт отдельным NUL-полем), `u`, `?`, заголовки `#`. Не делать split по пробелам для остатка с путём. Тайм-аут, отмена, предел stdout; при превышении показать ограничение, не «чисто». Не логировать содержимое файлов. [Формат Git](https://git-scm.com/docs/git-status).

Проверка: временный репозиторий, состояния clean, unborn, detached, `MM`, rename, конфликт, untracked, ignored, имя с пробелом/кириллицей. Ошибки `git-not-found`, `not-repository`, `outside-workspace` отличны от пустого списка.

### 2. Список изменений и выбор источника (Client)

В `client.js` добавить режим Source Control рядом с существующим проводником, внутри IDE, не в левую панель оболочки DSH. Сверху место для сообщения и действий; ниже секции «Подготовленные», «Изменения», при необходимости «Конфликты»; внизу отдельная сворачиваемая область «Граф». Строка = имя, приглушённый каталог, буквенный статус, tooltip с полным путём; счётчик секции считает строки этой секции. `MM` отображать дважды с разными ключами `{group,path}`. `?` — новый файл, не конфликт. Не использовать только цвет. Локализовать подписи RU/EN по принятому в клиенте образцу. Добавить доступ с клавиатуры.

Загружать при открытии, возврате фокуса, после сохранения в IDE и после Git-действия; кнопка обновления обязательна. Объединять серии запросов, отбрасывать ответы старой сессии/папки или старого номера запроса. Первую версию не снабжать постоянным рекурсивным watcher. Критерий: файл, изменённый вне DSH, появляется после возврата/обновления, а переключение режимов не закрывает dirty-вкладку.

### 3. Открыть правильное сравнение

`scmDiff({sessionId,group,path,revision}) → {before,after,beforeLabel,afterLabel,language}` либо типизированный fallback. Host находит строку в актуальном статусе. В группе «Изменения» сравнивать **индекс → файл на диске**, в «Подготовленных» — **HEAD → индекс**. Неподготовленный новый: пусто → диск; подготовленное добавление: пусто → индекс; удаление: прежнее → пусто. При rename читать старое имя только на прежней стороне, учитывая, в какой группе произошло переименование. Отсутствующая ожидаемая сторона — пусто, ошибка чтения — ошибка. Для конфликта сначала показать состояние и предложение разрешить вне панели; не изображать обычный двухсторонний diff.

Извлекать blob из дерева/индекса через Git, не через checkout. Для рабочего файла проверять физическую границу и тип **до** чтения; не следовать симлинкам наружу, gitlink не читать как каталог. Бинарные, неподдерживаемые кодировки и файлы больше установленного лимита (предложение: 2 МиБ на сторону) — карточка причины без передачи больших строк. Версия редактора в памяти не равна версии на диске: для dirty-файла явно подписать «На диске; есть несохранённые правки». Не сохранять автоматически.

Обобщить существующий просмотрщик только на уровне моделей и отображения. Ключ сравнения включает источник (`agent`/`git`), группу, сессию и последовательность запроса. Показать подписи сторон, переход к следующему/предыдущему отличию и «Открыть файл», если он существует. На desktop сохранить колонки и синхронный скролл Monaco, на узком экране — unified и видимый возврат к списку. Тест: HEAD=`A`, индекс=`B`, диск=`C` — две строки обязаны открыть соответственно A/B и B/C. Быстрый выбор второго файла не возвращает результат первого. Закрытие diff не меняет файл.

### 4. Локальные операции над индексом и коммит

Добавлять только после стабильного read-only режима. `scmStage`, `scmUnstage` получают выбранную строку и маркер просмотренной версии, `scmCommit` — непустое сообщение и маркер просмотренного индекса. Проверять разрешение записи для текущей сессии на Host; если политика не покрывает Git, оставить только чтение. Проверять соответствие сессии/корня, буквальные pathspec (`--literal-pathspecs` и `--`), свежесть данных, сериализовать операции одного worktree. При устаревании вернуть `stale`, предложить обновить. Для stage сверять и содержимое выбранного файла: одинаковый статус `M` не означает те же байты. Для commit сверять дерево индекса и HEAD. Внешний Git не подчиняется внутренней очереди: ошибки блокировки показать пользователю, чужой `index.lock` не удалять.

`+` готовит выбранный путь (`git add`), `−` снимает подготовку (`git restore --staged`, для unborn — убрать из индекса без удаления с диска); для rename обрабатывать пару путей. Кнопка «Фиксация» и Ctrl+Enter при фокусе в поле коммитят **только индекс**, без `-a`, без автоматического stage-all; сообщение передавать через stdin `git commit -F -`. Не запускать commit в недоверенном репозитории: хуки/фильтры Git могут выполнять программы. Ошибки hook/identity/lock отображать, черновик очищать только при успехе. Проверка: частично подготовленный файл после коммита остаётся изменённым на диске; HEAD содержит только подготовленную часть. Не добавлять push, reset --hard, clean или удаление untracked. Откат рабочего файла и операции по hunk — отдельное расширение с предпросмотром потери данных, не переиспользовать revert агента.

### 5. Нарисовать граф, связать коммит с его файлами

`scmHistory({sessionId,cursor?}) → {commits,nextCursor}`; строка `{oid,parents,subject,author,time,refs}`. Host получает топологический порядок из `git log --topo-order` с явно выбранными вершинами (HEAD, локальные и уже известные remote-tracking ветки); никакого fetch. Поля форматировать с NUL-разделителями, не парсить локализованный текст/ASCII-картинку. Первая страница 50 строк, кнопка «Ещё». Фиксировать вершины на первую страницу; при обновлении refs сбросить курсор. Для unborn показывать «Пока нет коммитов».

Маленькая чистая функция раскладки: хранить список ожидаемых OID по колонкам; узел занимает колонку своего OID либо новую; первого родителя продолжить по этой линии, остальных соединить с существующими/новыми колонками, завершённую линию закрыть. Переносить состояние линий через границу страниц. Рендерить сегменты и узлы в SVG слева от сообщения, рядом короткий SHA и метки HEAD/веток; текст и tooltip доступны без различения цветов. Unit-тесты на линейную цепочку, две ветки, merge и merge на границе страниц: каждый видимый родитель соединён со своим узлом.

Щелчок по коммиту → `scmCommitFiles` → список путей → исторический diff через тот же просмотрщик, без чтения текущих файлов. Передавать только OID из выданной истории; для корневого коммита база пустая, для merge по умолчанию первый родитель с явной подписью, затем разрешить выбор другого родителя. При удалении/rename использовать имена из diff дерева. Никакого checkout по клику. Тест: после изменения рабочего файла историческое сравнение остаётся прежним.

## Приёмка и границы

1. Использовать одноразовый Git-репозиторий с ветвлением, merge, staged+unstaged в одном файле и новым файлом. Не прогонять сценарии записи на пользовательских изменениях проекта. Host-тесты проверяют действительные состояния через отдельный вызов Git, client-тесты — выбор групп, ошибки, недоступность команд и устаревшие ответы.
2. Выполнить `npm run check` и `npm run test:all`; убедиться, что новый Host-модуль попадает в `npm pack --dry-run`, а тесты нового модуля действительно входят в `npm test`. Не менять `vendor/`, `editor/` или профиль пользователя ради прохождения тестов.
3. В тестовом профиле снять три кадра: широкий экран со списком и сравнением; история с реальным merge; узкий экран с unified-вариантом. Проверить тёмную/светлую темы, фокус, доступные названия и выход из diff обратно в редактор. Отдельно открыть старый diff агента. Без живой проверки не считать визуальный паритет подтверждённым.
4. Секция **Agent Review / Find Issues** образца — не функция Git. Если потребуется, следующей задачей подключить явный запуск проверки выбранного diff с показом базы и состава файлов. До этого не рисовать неработающую кнопку и не передавать содержимое модели автоматически. Распределить поставку: шаги 1–3 дают рабочий просмотр, 4 — локальную фиксацию, 5 — историю. Для соответствия запросу граф обязателен, даже если операции записи отключены политикой.
