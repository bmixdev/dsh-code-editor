# @local/dsh-ide

Рабочая среда в стиле VS Code внутри правой панели DeepSeek Harness: своё дерево
файлов, вкладки, быстрый поиск и редактор Monaco с ИИ-подсказками. Плагин не
зависит от встроенного файлового браузера — дерево строит сам Host-половина
плагина через `node:fs` и проверку границ рабочей папки.

## Возможности

- **Дерево рабочей папки.** Открывается сразу при входе в IDE: ленивая подгрузка
  каталогов, иконки типов файлов, гайды вложенности, переключатель скрытых
  файлов, кнопка обновления и фильтр по имени (при вводе запроса дерево
  переключается на плоский поиск по всему рабочему каталогу).
- **Вкладки.** Несколько файлов одновременно, точка несохранённых изменений,
  закрытие вкладки (крестик или средняя кнопка мыши), `Ctrl+S` — сохранить,
  `Ctrl+Shift+S` — сохранить все, `Ctrl+W` — закрыть вкладку.
- **Быстрый поиск `Ctrl+P`.** Нечёткий поиск по путям рабочей папки, стрелки и
  `Enter` работают как в VS Code.
- **Редактор Monaco.** Одна модель на вкладку, сохранение позиции и скролла,
  подсветка языка, тёмная и светлая темы в палитре VS Code, изменяемая ширина
  дерева.
- **ИИ-подсказки.** Inline-подсказки при наборе и `Ctrl+Space` для принудительного
  запроса; модель и провайдер выбираются в панели настроек, ключ API хранится в
  хранилище секретов DSH. Разрешение отправлять текст модели выдаётся один раз на
  рабочую папку: в редакторе появляется полоса «Включить» / «Не сейчас», а само
  разрешение запоминается в `~/.dsh/code-editor.json` и переживает перезапуск DSH.
- **Вид VS Code.** Узкая панель активности слева (проводник, быстрый поиск,
  настройки), заголовок секции «ПРОВОДНИК» с действиями, вкладки как в VS Code,
  синий статус-бар, меню `☰` с командами «Сохранить», «Сохранить всё»,
  «Закрыть вкладку», «Открыть файл по имени», «Настройки IDE».
- **Статус-бар.** Язык файла, позиция курсора, переводы строк, UTF-8, режим
  «только чтение», текущая модель автодополнения.
- **Сохранение состояния.** Открытые вкладки, активный файл, ширина дерева и
  видимость скрытых файлов запоминаются для каждой сессии
  (`~/.dsh/ide-state.json`).

## Как открыть

Кнопка **IDE** появляется в четырёх местах:

- строка **IDE** на вкладке **Старт** — самое заметное место, ничего открывать не
  нужно;
- кнопка **IDE** в панели ввода рядом с режимами доступа (в сессии она видна
  всегда);
- кнопка **IDE** в инструментах вкладки файла или вкладки **Файлы**;
- заголовок самой вкладки IDE: имя открытого файла.

Вкладка файла открывается сразу с этим файлом и деревом рабочей папки; из
«Старта», панели ввода и «Файлов» IDE открывается на корне рабочей папки —
достаточно выбрать файл в дереве или нажать `Ctrl+P`. На сессию приходится одна
вкладка IDE: повторное открытие не плодит вкладки, а показывает уже открытую.

## Установка

Плагин ставится как обычный локальный бандл DSH: путь `ide/` указывается либо в
управлении плагинами DSH (пункт «установить бандл» с путём `link:...`), либо
напрямую в профиле:

```json
{
  "dependencies": {
    "@local/dsh-ide": "link:C:/path/to/dsh-code-editor/ide"
  },
  "dsh": {
    "profile": {
      "bundles": ["@local/dsh-ide"]
    }
  }
}
```

После установки перезапустите DSH: Host-половина регистрирует маршруты
`/api/ide/*` и раздаёт Monaco по `/ide/vs/*`, клиентская половина добавляет
вкладку и кнопку «IDE» в шапку открытого файла.

Файл `package.json` профиля должен быть **UTF-8 без BOM** — загрузчик читает его
через `JSON.parse`, и метка BOM валит запуск. Проверить все манифесты можно
командой `npm run check` из корня репозитория.

| Дополнительные действия | кнопка «⋯» в шапке проводника: обновить, свернуть всё, скрытые файлы, копировать путь рабочей папки |

## Меню

Верхняя строка повторяет состав меню VS Code: «Файл», «Правка», «Выделение»,
«Вид», «Переход», «Запуск», «Терминал», «Справка». Пункты, которые редактор выполнить не
может, остаются на месте, но отключены — причина написана во всплывающей
подсказке, чтобы не было иллюзии поддержки.

| Меню | Работает | Отключено (и почему) |
| --- | --- | --- |
| Файл | новый файл, открыть по имени, сохранить, сохранить всё, закрыть вкладку, закрыть все, обновить дерево, показать/скрыть проводник | «Открыть папку» — рабочую папку задаёт сессия DSH |
| Правка | отменить, повторить, вырезать, копировать, вставить, найти, заменить | «Форматировать документ» — нужен языковой сервис |
| Выделение | выделить всё, выделить строку, расширить, сузить | — |
| Переход | к файлу, к строке, в начало/конец файла, следующая/предыдущая вкладка | «Перейти к определению» — нужен LSP |
| Вид | перенос по словам, скрытые файлы, масштаб шрифта, настройки | «Проблемы» — нужна диагностика языковых сервисов |
| Запуск | — | «Запуск без отладки» — нет PTY, «Запуск с отладкой» — нет отладчика, «launch.json» — не применяется |
| Терминал | — | «Новый терминал» — у плагина нет доступа к PTY; терминал DSH живёт отдельной вкладкой |
| Справка | о плагине, горячие клавиши | — |

«Новый файл» создаёт пустой файл внутри рабочей папки (родительские каталоги
создаются, существующий файл не перезаписывается) и сразу открывает его.

## Панель вывода

Внизу редактора есть панель как в VS Code. `Ctrl+Space` открывает её при
каждом ручном запросе подсказки, а Ctrl и обратная кавычка (или «Вид → Показать
панель вывода») — в любой момент. Высоту панели можно менять, потянув разделитель
над ней; она запоминается в состоянии сессии (`~/.dsh/ide-state.json`).

- **Траектория** — строка на каждый запрос автодополнения: время, файл, провайдер
  и модель, режим (авто или `Ctrl+Space`), сколько символов контекста ушло,
  длительность, результат («+N символов») или причина, почему ответ пустой.
- **Чат** — что именно было отправлено модели (системная инструкция и текст с
  маркерами курсора) и что она вернула.

Это же объясняет самый частый вопрос «почему подсказки не работают»: у
рассуждающей модели (`reasoning`) скрытое размышление съедало весь бюджет
токенов, и ответ приходил пустым. Теперь плагин:

- запрашивает у модели минимальный advertised `reasoningEffort`, оставляя бюджет
  на код;
- поднимает лимит ответа до 900 токенов;
- возвращает причину пустого ответа в панель, вместо молчаливого «ничего».

## Настройки

Страница настроек (шестерёнка в шапке, `Ctrl+,` или «Вид → Настройки IDE…»)
сделана как в VS Code: заголовок с поиском, разделы слева, строки «название и
описание слева, контрол справа». Значения хранятся в общем файле
`~/.dsh/code-editor.json` (тот же, что использует плагин
`@local/dsh-code-editor`) и применяются сразу:

- провайдер и модель автодополнения (со списком из живого каталога DSH);
- кнопка «Обновить каталог» и сообщения провайдеров, которые не отдали модели;
- автоподсказки при наборе;
- имя ключа API и сам ключ — значение уходит в хранилище секретов DSH, в файл
  настроек попадает только имя (`apiKeyRef`);
- сколько символов до и после курсора отправлять в модель (200–20000 и 0–8000).

## Безопасность

- Пути проверяются через `ctx.fs.resolve` / `ctx.fs.contains`, включая защиту от
  символических ссылок: за пределы рабочей папки дерево не выходит.
- Скрытые каталоги (`.git`, `node_modules`, `dist`, `build`, `.venv`, `target` и
  другие) не листаются и в быстрый поиск не попадают.
- Список файлов ограничен 400 записями на каталог и 20000 записей на поиск.
- Файлы больше 1 МиБ не открываются; бинарные и не-UTF-8 файлы отклоняются.
- Ключи API никогда не пишутся в файл настроек и не возвращаются клиенту в
  открытом виде — только маска из хранилища.

## Тесты

```powershell
cd ide
node --test tests/host.test.mjs tests/client.test.mjs
```

`host.test.mjs` поднимает фейковый контекст, собирает маршруты `/api/ide/*` и
проверяет дерево, быстрый поиск, открытие/сохранение, состояние сессии, общие
настройки и деградацию без хранилища ключей. `client.test.mjs` загружает бандл
через `__ModuleLoader__` с заглушкой React и проверяет регистрации: тип вкладки,
слоты, кнопку «IDE», защиту от закрытия грязных вкладок и заголовок вкладки.

## Структура

```
ide/
  index.js          Host: маршруты /api/ide/*, раздача Monaco
  client.js         Клиент: дерево, вкладки, Monaco, настройки
  state.js          Состояние вкладок по сессиям (~/.dsh/ide-state.json)
  catalog.js        Провайдеры, модели и ключи (общий с редактором)
  completion.js     Контекст и постобработка подсказок (общий)
  prefs.js          Настройки ~/.dsh/code-editor.json (общий)
  tree.js           Листинг каталогов и быстрый поиск (общий)
  vendor/vs/        Сборка Monaco
  tests/            host.test.mjs, client.test.mjs, sync.test.mjs
```

Четыре общих модуля лежат в корне репозитория и продублированы внутрь `ide/`,
чтобы бандл можно было установить из любой папки. `ide/tests/sync.test.mjs`
сравнивает копии с оригиналами байт в байт: после правки корневого модуля
скопируйте его в `ide/` снова.

## Ограничения

- Один редактор на вкладку правой панели; одновременно открытые IDE-вкладки в
  разных сессиях независимы.
- Быстрый поиск — по путям, без поиска по содержимому файлов.
- Diff-режим, рефакторинги и LSP не входят в эту версию.
