# Редактор кода для DeepSeek Harness

`@local/dsh-code-editor` — вспомогательный бандл этого репозитория (папка
`editor/`). Главный плагин — [`@local/dsh-ide`](../README.md): среда в стиле
VS Code с деревом, вкладками и быстрым поиском.

Плагин добавляет в правую панель DeepSeek Harness вкладку с редактором
[Monaco](https://microsoft.github.io/monaco-editor/): дерево файлов рабочей
папки, правку открытого файла с проверкой версии при сохранении, строчные
подсказки модели (Tab), замер задержки и кнопку «В чат».

Всё, что можно настроить, настраивается из самого редактора: кнопка **⚙** в
тулбаре открывает панель настроек — провайдер и модель автодополнения, ключ
API, размер контекста, дерево файлов и автоподсказки.

Этот редактор — второй, вспомогательный бандл репозитория. Он использует те же
настройки и ключи, что и IDE, но ставится и включается отдельно и не требует
`@local/dsh-ide`: достаточно папки `editor/`.

## Возможности

* **Вкладка редактора.** Превью документа получает кнопку «Редактировать»;
  файл открывается в соседней вкладке с Monaco. Вкладка адресуется той же
  ресурсной строкой (`dsh-resource://file/session/<sessionId>/<path>`), но
  собственным `kind`, поэтому превью и редактор одного файла — разные вкладки.
* **Дерево файлов** (кнопка «Файлы»). Папки раскрываются по клику, файл
  открывается в редакторе, фильтр по имени подсвечивает совпадения в уже
  загруженных каталогах. Показываются все каталоги, включая `node_modules`,
  `dist`, `.git` и `target`; большой каталог читается страницами, когда его
  раскрывают. Точка-файлы скрыты по умолчанию.
* **Строчные подсказки** модели: `Tab` принимает, `Esc` отклоняет,
  `Ctrl+Space` просит подсказку вручную. Подсказки включаются для рабочей папки
  сессии кнопкой «Tab-подсказки» и требуют явного согласия; согласие
  запоминается в `~/.dsh/code-editor.json` и переживает перезапуск DSH.
* **Настройки в интерфейсе:** выбор провайдера и модели автодополнения отдельно
  от модели чата, каталог моделей с обновлением, ключ API провайдера, лимиты
  контекста, дерево и автоподсказки.
* **Сохранение с проверкой версии.** `Ctrl+S` пишет через `ctx.fs` с
  `replaceIfVersion`: если файл изменился на диске, сохранение отклоняется, а не
  затирает чужие правки. BOM и переводы строк (`CRLF`/`LF`) сохраняются.
* **«В чат».** Выделение (или весь буфер) вставляется черновиком в поле ввода
  текущего чата с подписью `путь:строки · из буфера`.
* **Замер задержки** по `Ctrl+Alt+B`: 100 запросов подсказки, p50/p95/max.

## Как открыть редактор

1. Откройте файл в правой панели обычным способом (ссылка на файл, `@file`).
2. В шапке превью нажмите **«Редактировать»**.

Поддерживаются существующие файлы UTF-8 внутри рабочей папки сессии (включая
worktree) размером не больше 1 МиБ. Бинарные и не-UTF-8 файлы остаются в обычном
превью. Сессия в режиме «только чтение» остаётся в нём: сохранение отклоняет
песочница.

## Настройки (⚙)

| Поле | Что делает | По умолчанию |
| --- | --- | --- |
| Провайдер автодополнения | Из какого провайдера брать модель. «Как у сессии» — текущая модель DSH | как у сессии |
| Модель автодополнения | Конкретная модель. «Первая доступная» — первый id каталога провайдера | модель сессии |
| Обновить каталог | Перечитывает провайдеров и модели у Host | — |
| Автоподсказки | Показывать подсказку без `Ctrl+Space` | включено |
| Дерево файлов | Открывать редактор с деревом | включено |
| Скрытые файлы | Показывать точка-файлы в дереве | выключено |
| Символов до/после курсора | Размер контекста запроса (200–20000 / 0–8000) | 4000 / 1000 |
| API-ключ провайдера | Сохранение/удаление ключа в хранилище ключей DSH | — |

Настройки редактора — машино-локальный файл `~/.dsh/code-editor.json`
(переопределяется переменной `DSH_CODE_EDITOR_PREFS`). Конфигурацию DSH плагин
не переписывает.

**Ключи API в этом файле не хранятся.** Ключ кладётся в штатное хранилище
секретов DSH (`~/.dsh/.credentials.yaml`), а панель показывает только статус:
настроен ли ключ, откуда он взят (`store`/`env`), и маску. Имя ключа берётся из
профиля провайдера (`apiKeyEnv`), поэтому вписывать его вручную нужно только
для нестандартного провайдера.

## Дерево файлов

* Листинг идёт по `node:fs`, но каждый каталог сначала разрешается через
  `ctx.fs` и проверяется на вложенность в рабочую папку, поэтому выйти за её
  пределы нельзя (ошибка `outside-workspace`).
* Показываются все каталоги, включая `node_modules`, `dist`, `build`, `.git`,
  `target` и `__pycache__`: дерево ничего не скрывает по имени. Каталог читается
  только при раскрытии, поэтому большой каталог ничего не стоит, пока в него не
  зашли.
* Список отдаётся страницами по 400 записей (до 2000 за запрос); в конце списка
  есть строка «Показать ещё», которая догружает следующую страницу.
* Открытие файла при несохранённых правках сначала просит сохранить
  (`Ctrl+S`), чтобы не потерять изменения.

## Подсказки (Tab)

* Разрешение на подсказки выдаётся кнопкой **«Tab-подсказки»** для рабочей папки
  сессии и живёт в памяти Host до перезапуска DSH. Перед включением показывается
  панель с выбранными провайдером/моделью, размером контекста и предупреждением,
  что inline-запрос не пишется отдельным сообщением в журнал сессии (хранение на
  стороне провайдера зависит от его политики).
* «Исключить файл» выключает подсказки только для текущего файла.
* По умолчанию запрещены `.env*`, ключи и сертификаты (`*.pem`, `*.key`, `*.p12`,
  `*.pfx`, `keystore`), `.ssh`, `id_rsa` и типовые файлы credentials/secrets;
  Host перепроверяет путь перед запросом.
* Запрос уходит не раньше чем через 200 мс после последнего ввода и несёт
  ≤4000 символов до курсора и ≤1000 после (лимиты меняются в настройках).
  Таймаут — 20 с. Ошибка, отсутствие модели или сети просто не показывают
  подсказку: редактор продолжает работать.
* Если модель израсходовала лимит на рассуждения и вернула пустой ответ,
  подсказка не появляется; в настройках можно выбрать нерассуждающую модель
  именно для автодополнения.

## Замер задержки

Кнопка «Замер» (или `Ctrl+Alt+B`) делает 100 последовательных запросов подсказки
на выбранной модели и показывает `p50 · p95 · max`. В обычной работе лишних
запросов нет.

## Установка

Плагин не требует сборки: `index.js` (Host) и `client.js` (Client) — готовые
модули, Monaco лежит в `vendor/vs` и раздаётся Host-половиной с
`/code-editor/vs` (без CDN и ослабления CSP).

Ставить нужно именно папку `editor/`: корень репозитория — это другой бандл
(`@local/dsh-ide`).

Вариант 1 — менеджер плагинов:

```
plugin_manager action=install_bundle target=<абсолютный путь к папке editor/>
```

Вариант 2 — вручную в профиле DSH (`~/.dsh/profiles/<profile>/package.json`):

```json
{
  "dependencies": { "@local/dsh-code-editor": "link:C:/path/to/dsh-code-editor/editor" },
  "dsh": { "profile": { "bundles": ["@local/dsh-code-editor"] } }
}
```

После установки перезапустите DSH: Host-половина регистрирует новые маршруты
(`/api/code-editor/{tree,catalog,credentials,prefs}`) только при загрузке
плагина, поэтому без перезапуска дерево и настройки останутся недоступны, а
редактор будет работать на встроенных значениях. Затем обновите страницу GUI —
клиентский модуль подхватывается при загрузке страницы.

Быстрая проверка после перезапуска:

1. Откройте файл сессии в правой панели и нажмите «Редактировать».
2. Кнопка «Файлы» показывает дерево рабочей папки, поле в дереве фильтрует его по имени.
3. Кнопка «⚙» открывает настройки: провайдер и модель подсказок, ключ API, размер контекста.
4. «Сохранить настройки» пишет `~/.dsh/code-editor.json` (или файл из переменной `DSH_CODE_EDITOR_PREFS`).

### Манифест профиля: только UTF-8 без BOM

DSH читает `~/.dsh/profiles/<profile>/package.json` как `JSON.parse` от строки из
`readFileSync(..., 'utf8')`, а `JSON.parse` не снимает BOM. Один
`Set-Content -Encoding utf8` в Windows PowerShell добавляет `EF BB BF` — и
следующий старт падает с `DesktopHostFatalError: Unexpected token '\uFEFF'`, ещё до
загрузки плагинов. Поэтому манифест профиля правьте так:

```powershell
# PowerShell 5.1: .NET API, без BOM
$json = Get-Content -Raw -Encoding UTF8 .\package.json
[IO.File]::WriteAllText((Resolve-Path .\package.json), $json, [Text.UTF8Encoding]::new($false))
```

```js
// Node
await fs.writeFile(file, `${JSON.stringify(value, null, 2)}\n`, 'utf8')
```

Проверка перед выпуском и после правки профиля:

```
npm run check
```

`scripts/check-manifests.mjs` обходит репозиторий и профили в `~/.dsh`, ищет BOM
в текстовых файлах, проверяет `package.json` через `JSON.parse` и падает с
кодом 1, если что-то не так.

## Тесты

Из папки `editor/`:

```
npm run check
npm test
```

Или из корня репозитория — `npm run test:editor` (плюс `npm run test:all`, если
нужны тесты обоих бандлов).

`tests/host-smoke.mjs` — открытие/сохранение/подсказки через фейковый Host,
`tests/editor-state.test.mjs` — настройки, дерево, каталог моделей и ключи,
`tests/client-smoke.test.mjs` — загрузка клиентского бандла через
`__ModuleLoader__` и регистрация вкладки, слотов и защиты от закрытия,
`tests/completion.test.mjs` — фильтры постобработки ответа,
`tests/sync.test.mjs` — совпадение общих модулей с корневыми копиями.

## Структура

```
editor/
  index.js          Host: маршруты /api/code-editor/*, вызов модели, статика Monaco
  client.js         Client: вкладка, дерево, панель настроек, inline-подсказки
  completion.js     построение контекста и фильтры ответа (общий)
  tree.js           листинг каталогов для дерева (общий)
  catalog.js        каталог провайдеров/моделей и работа с хранилищем ключей (общий)
  prefs.js          машино-локальные настройки редактора (общий)
  vendor/vs         Monaco (MIT), собранный статикой
  tests/            node:test
```

Четыре общих модуля продублированы из корня репозитория, чтобы редактор можно
было установить из любой папки. `tests/sync.test.mjs` сверяет копии с
оригиналами байт в байт: после правки корневого модуля скопируйте его сюда
снова.

## Ограничения

* Нет автодополнения по диапазону (замены участка кода) — только вставка в
  позицию курсора.
* Нет нескольких курсоров, диффов и сохранения по таймеру.
* LSP не подключён: Monaco работает со своей подсветкой и без языковых серверов.

## English summary

A secondary, optional Monaco code editor plugin for DeepSeek Harness (the
repository's main plugin is `@local/dsh-ide` at the root): an editor tab in the
right sidebar, a file tree of the session workspace, AI inline completions (Tab /
Ctrl+Space) with a provider-and-model chooser, an in-app settings drawer, API key
storage through the DSH credential store, guarded save with version checks, and
"quote to chat". Install the `editor/` folder with
`plugin_manager action=install_bundle target=<absolute path to editor/>`; run
tests with `npm test` inside `editor/` or `npm run test:editor` from the root.
MIT licensed.
