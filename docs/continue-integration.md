# Continue в редакторе DSH: план выборочного встраивания

Предлагается сохранить Monaco и текущий чат DSH, а из Continue перенести только те алгоритмы подготовки и очистки подсказок, которые покажут пользу на коде проекта.
Это дополнение к [базовому плану редактора](./dsh-code-editor.md), а не замена его этапов открытия, цитирования и сохранения файла.
Статус: предложение для пилота. Плагин не реализован; совместимость, качество и задержка не измерены.

## Состояние реализации

Часть плана выполнена: операции без I/O перенесены в `plugins/dsh-code-editor/completion.js` (подготовка `prefix/suffix` и постобработка ответа), подключены в `complete` файла `plugins/dsh-code-editor/index.js` и покрыты `plugins/dsh-code-editor/tests/completion.test.mjs`. Итог прогона: `node --test tests/completion.test.mjs tests/host-smoke.mjs` — 24 теста, 24 проходят, 0 падений. Перенесены `lineIsRepeated` со своим Levenshtein, `stopAtLines`/`skipPrefixes`/`skipLines`/`removeTrailingWhitespace`/`filterLeadingNewline`/`avoidPathLine`/`noTopLevelKeywordsMidline`/`stopAtRepeatingLines`, `validatePatternInLine`, `rewritesLineAbove`, `isExtremeRepetition`, `removeBackticks`, дедупликация пробела и форма `constructInitialPrefixSuffix`. Не перенесены: блок `llm.model.includes(...)`, `lineFilters`/`charFilters`, кэш, diff-движок.

**Шаг 2 выполнен** (см. ниже): клиентская половина перестала резать окна сама и отправляет буфер с `offset`, а границы окна и бюджет задаёт Host. Окно запрашивается полем `contextLeft`/`contextRight` и зажимается `boundedWindow` к конфигурированному бюджету — клиент не может расширить его сверх `CONTEXT_LEFT`/`CONTEXT_RIGHT`. Размер буфера ограничен `MAX_CONTEXT_TEXT_CHARS` (4 МиБ); превышение отклоняется кодом `context-too-large` до обращения к модели. Шаги 3-5 (проверка без сети, замер пользы, поставка) остаются невыполненными.

## Что встраивать, а что оставить в DSH

| Сценарий | Решение и причина |
|---|---|
| Дополнение по Tab | Сравнить базовый запрос DSH с выборочным переносом логики Continue: бюджет токенов для текста до и после курсора, выбор многострочной вставки и постобработка результата. Подсказку показывает Monaco, принимает пользователь. |
| Выделение в чат | Оставить штатное цитирование из несохранённого буфера в черновик текущей сессии по базовому плану. Continue здесь не решает новой задачи. |
| Правка выделения | После пилота: запросить замену выбранного диапазона, показать diff, применить к буферу только после подтверждения и проверки версии. Сохранение — отдельное действие. Это предлагаемая функция DSH, не обещание совместимости с Continue Edit. |
| Расширенный контекст | Сначала только активный буфер. Позже сравнить результат с явно выбранным вторым фрагментом. Индекс репозитория, embeddings и LSP не вводить до доказанной необходимости. |
| Агент, CLI и чат Continue | Не запускать параллельно с агентом DSH: появятся вторые история, настройки провайдера и контур разрешений. Готовое расширение Continue в любой внешней среде — альтернатива, если одно окно и общий черновик больше не обязательны; Monaco сам по себе не является хостом расширений. |

## Точка интеграции

`Monaco → снимок буфера → Host DSH: политика и бюджет → подготовка запроса → выбранная модель → очистка вставки → Monaco`

[CompletionProvider Continue](https://github.com/continuedev/continue/blob/main/core/autocomplete/CompletionProvider.ts) — **образец оркестрации, не готовая библиотека для импорта**. Конструктор требует `ConfigHandler`, `IDE`, `ILLM` и поиск определений LSP; выполнение обращается к workspace, сервисам контекста, кэшу и журналу. Для некоторых OpenAI-моделей код переключает legacy completions. Перенос класса целиком изменил бы и состав данных, и маршрут запросов.

Граница заимствования: две операции без I/O — подготовить ограниченные `prefix/suffix` и обработать текст ответа. У них нет доступа к диску, сети, ключам, истории чата или модели Monaco. Отмена, выбор модели, передача запроса и обязательный журнал остаются у Host DSH. Не переносить кэш Continue: поиск по усечённому префиксу не различает одинаковое начало с разным суффиксом. В пилоте кэша нет.

## Границы заимствования по файлам

Прочитано по commit `5522c6f4`. Файлы перечислены с тем, что берём и что не берём.

**`core/autocomplete/filtering/streamTransforms/lineStream.ts`** — основной источник. Берём регулярные и строковые преобразования, у которых нет зависимостей кроме самого текста:

| Функция | Что делает |
|---|---|
| `lineIsRepeated(a, b)` | `false`, если любая строка ≤ 4 символов; иначе `levenshtein(a.trim(), b.trim()) / b.trim().length < 0.1`. Нужен свой Levenshtein: Continue тянет `fastest-levenshtein` |
| `stopAtRepeatingLines` | останавливает поток после `MAX_REPEATS = 3` одинаковых строк подряд; первая из повторов отдаётся |
| `stopAtSimilarLine` | не стопает на пустой эталонной строке; для строк, оканчивающихся на `) ] } ;`, разрешает точное совпадение |
| `stopAtLines` | стоп по подстроке, но только если она стоит в логическом начале строки или отделена пробелом |
| `skipPrefixes` | срезает префикс только у первой строки, `PREFIXES_TO_SKIP = ["<COMPLETION>"]` |
| `skipLines` | выбрасывает строки с префиксами `LINES_TO_SKIP = ["</START EDITING HERE>", "<|updated_code|>"]` |
| `removeTrailingWhitespace` | `line.trimEnd()` на каждой строке |
| `filterLeadingNewline` | убирает только самую первую пустую строку |
| `filterEnglishLinesAtStart` / `...AtEnd` | режет английские пояснения по спискам `ENGLISH_START_PHRASES` и `ENGLISH_POST_PHRASES` |
| `noDoubleNewLine` | прекращает поток на первой пустой строке, кроме самой первой |
| `avoidPathLine` | выбрасывает строки вида `// Path: <путь>`, которые модель копирует из вставленных сниппетов |
| `noTopLevelKeywordsMidline` | обрывает строку на top-level ключевом слове, если оно не в начале строки |
| `showWhateverWeHaveAtXMs` | отдаёт накопленное через заданный таймаут, если уже есть непустая строка |

`validatePatternInLine(line, pattern)` — вспомогательная эвристика, на которой стоят `stopAtLines` и `shouldChangeLineAndStop`: паттерн не считается найденным, если перед ним непробельный символ (значит, часть идентификатора) или нечётное число `'` / `"` (значит, внутри строкового литерала).

Не берём: `logLines`, `filterLeadingAndTrailingNewLineInsertion`, `fixCodeLlamaFirstLineIndentation`, `streamWithNewLines`, `processBlockNesting`, `hasNestedMarkdownBlocks` — это либо отладка, либо части diff-движка Continue.

**`core/autocomplete/postprocessing/index.ts`** — `postprocessCompletion({completion, llm, prefix, suffix})`. Переносимая часть: отказ на пустом и пробельном ответе, `rewritesLineAbove` (первая непустая строка вставки повторяет строку выше), `isExtremeRepetition` (не менее 6 строк, LCS первой строки с последующими), дедупликация пробела при `prefix.endsWith(" ") && completion.startsWith(" ")`, `removeBackticks`.

Не переносить блок с `llm.model.includes(...)`: `codestral`, `qwen3` (срезание ` thinking...</think>`), `granite`, `mercury`, `gemini`/`gemma` — это внутренние костыли Continue под конкретные модели, а не свойство алгоритма. Если такая правка понадобится, её следует привязать к провайдеру DSH, а не копировать список.

**`core/autocomplete/templating/constructPrefixSuffix.ts`** — `constructInitialPrefixSuffix(input, fileContents)`. Копировать форму, а не код: префикс — текст от начала файла до позиции курсора (или до начала выделения) плюс выделенный текст, суффикс — текст от позиции до конца, оба ограничены бюджетом. Своя реализация проще, чем зависимости Continue (`getRangeInString`, типы `AutocompleteInput`).

**`core/autocomplete/constants/AutocompleteLanguageInfo.ts`** — берём форму интерфейса `AutocompleteLanguageInfo` (`name`, `topLevelKeywords`, `singleLineComment?`, `endOfLine`, `lineFilters?`, `charFilters?`, `useMultiline?`) и таблицу `LANGUAGES` по расширению файла с фолбэком на TypeScript. Нужна для `noTopLevelKeywordsMidline` и для выбора `singleLineComment` при подстановке контекста. `lineFilters` для YAML и `charFilters` для JSON (через `BracketMatchingService`) — отдельные решения, в пилот не входят.

**`core/autocomplete/CompletionProvider.ts`** — образец оркестрации, не библиотека. Подтверждено чтением: конструктор требует `ConfigHandler`, `IDE`, `ILLM` и поиск определений LSP, выполнение обращается к workspace, сервисам контекста, кэшу и журналу. Класс целиком не переносить.

Client передаёт идентификаторы сессии и документа, версию буфера, позицию, язык и ограниченное окно текста. Host сверяет принадлежность документа и разрешение на передачу **до** вызова модели; исключённые и секретные файлы не отправляются. При смене позиции, версии или сессии ответ отбрасывается даже при запоздалой отмене. Возвращается текст вставки, не команда записи. FIM включается только при подтверждённой поддержке адаптером и моделью. Иначе используется базовая генерация вставки через чат-модель; конфигурация основного чата не меняется. Внешний редактор-образец, его вход и локальный шлюз не являются зависимостями пилота.

Фактическая разбивка после шага 2: клиент отправляет `{ text, offset, selection, contextLeft, contextRight }`, а `buildContext` в Host вырезает окна. Бюджет не является доверенным вводом — `boundedWindow` зажимает оба числа к `CONTEXT_LEFT = 4000` и `CONTEXT_RIGHT = 1000`, а `open`/`settings` возвращают клиенту `context: { left, right }`, чтобы текст согласия показывал настоящий бюджет, а не константу в интерфейсе. Для задержки клиент берёт базовую линию не из живого буфера в момент запроса (пауза `COMPLETION_PAUSE_MS = 200` уже добавила бы нажатия в буфер), а из `committedText`/`committedOffset`, снятых при изменении буфера сразу после показа предыдущей вставки; иначе ожидание засчитывается модели.

## Порядок работ и критерии перехода

1. **Зафиксировать исходники.** Commit зафиксирован: `5522c6f44ca0ac3528b37244818fbfa39b5af470` (21.07.2026). Список заимствуемых функций — в разделе «Границы заимствования по файлам» ниже. Проверить лицензии каждого заимствования; Continue распространяется под Apache-2.0, поэтому сохранить лицензию, применимые уведомления и отметить изменения. Если функция требует файловой системы или загрузки всего `core`, не включать её; воспроизвести нужное поведение своим небольшим модулем или остаться на базовом варианте. **Выполнено:** лицензия проверена, `completion.js` несёт уведомление и перечень изменений.
2. **Подготовить сравнение.** **Выполнено в части отправки контекста:** клиент отправляет буфер, `offset` и выделение, а окна и их бюджет считает Host; базовый и экспериментальный режимы различаются только подготовкой и очисткой вставки. Осталось: переключатель режимов в интерфейсе, чтобы сравнивать их на одних и тех же позициях. Одни и те же модель, буферы, позиции, лимиты и транспорт. Контрольные случаи: вставка перед закрывающей скобкой, уже существующая следующая строка, незавершённый блок, кириллица, пустой суффикс, правка без сохранения. FIM сравнивать отдельно, чтобы не приписать алгоритму эффект другой модели.
3. **Проверить корректность без сети.** Фиктивный провайдер возвращает многострочный, пустой и запоздавший ответ. Проверить Tab, Esc и Undo, обычный отступ без подсказки, отказ на исключённом пути, отсутствие запроса после отключения, две сессии с одинаковым путём. При любой ошибке провайдера ввод и цитирование должны работать. Ни один ответ не пишет файл.
4. **Измерить пользу.** На одних и тех же позициях провести не менее 100 запросов на режим. Считать полезной вставку, которую проверяющий принял бы без исправления; отдельно считать дубли суффикса, стоимость на 100 запросов и p50/p95 от последнего нажатия до показа. Цели базового плана: p50 ≤ 500 мс, p95 ≤ 1,5 с. Оставить перенос, только если выросла доля полезных вставок, не выросла доля дублей, соблюдены цели задержки и согласованный до прогона бюджет. При неоднозначном результате оставить базовый режим по умолчанию.
5. **Поставка и откат.** Сначала включать эксперимент только вручную в выбранном workspace; перед включением показать провайдера, границы отправляемого кода и правила журнала. Откат — отключить эксперимент, отменить активный запрос и вернуть базовый Tab без миграции файлов или истории. Лишь затем отдельно решать, нужен ли редактору diff или дополнительный контекст.
